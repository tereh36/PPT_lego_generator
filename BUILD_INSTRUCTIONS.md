# LEGO Lesson Generator — приложение (Electron)

Настоящее desktop-приложение с интерфейсом: вкладки Preschool/Brickmoto,
настройки (API-ключ, режим картинок), поле темы, кнопка "Создать презентацию".

## Что нужно один раз сделать, чтобы получить рабочий .exe

### Шаг 0 — что нужно на компьютере, где собираете .exe
Только Node.js (Python больше не нужен нигде — ни для сборки, ни для конечного
пользователя, всё переписано на Node/pdfkit/jszip).
Дополнительно понадобится доступ в интернет на момент сборки (скачать Electron).

### Шаг 1 — установить зависимости
В PowerShell, находясь в папке `LegoLessonApp`:
```
npm install
```
Это займёт больше времени, чем раньше (Electron — большой пакет, ~150-200 МБ),
подождите, пока команда полностью закончится.

### Шаг 2 — попробовать приложение без сборки в .exe (быстрая проверка)
```
npm start
```
Откроется окно приложения. Если всё выглядит нормально — переходите к сборке.
Закройте окно, чтобы продолжить.

### Шаг 3 — автообновление уже настроено
В `package.json` уже вписан ваш репозиторий (`Tereh36/PPT_lego_generator`) —
ничего менять не нужно, можно сразу переходить к сборке.

### Шаг 4 — собрать .exe
```
npm run build
```
Тоже займёт время (несколько минут). По завершении в папке `dist/` появится
установочный файл вида `Star-Team-Setup-1.6.13.exe` — это и есть
готовый инсталлятор, который можно передавать/устанавливать как обычную программу.

**Проверка зависимостей при сборке.** `npm run build` в конце сам запускает
`tools/verify-packaged-deps.js`. Он проходит по собранному приложению и
проверяет, что каждый модуль реально находится оттуда, откуда его требуют.
Это нужно потому, что electron-builder не копирует `node_modules` как есть, а
пересобирает дерево и иногда кладёт общий пакет внутрь одного из зависимых
вместо корня — тогда все остальные его не видят. Именно так в 1.6.12 сломался
печатный PDF: `pdfkit` не грузился, презентация собиралась, а PDF — нет.
Хук `tools/after-pack.js` чинит такие случаи автоматически прямо во время
сборки, а проверка в конце — страховка.

Если проверка написала **BUILD IS BROKEN** — инсталлятор собрался, но им
нельзя пользоваться: у пользователя отвалится какая-то функция. Сначала
почините список модулей, потом собирайте заново.

### Шаг 5 — выложить на GitHub (для автообновлений)
1. Зайдите в свой репозиторий на github.com
2. Справа — раздел **"Releases"** → **"Create a new release"**
3. **Tag**: `v1.0.0` (важно — версия должна совпадать с `version` в `package.json`)
4. Прикрепите файлы из папки `dist/`: `.exe`, `latest.yml` (этот файл нужен
   именно для автообновления — не пропустите его)
5. Нажмите **"Publish release"**

Готово — этот `.exe` теперь можно передать кому угодно, установить как обычную
программу, и при выходе новой версии (шаги 4-5 повторяются с новым номером
версии) приложение само это заметит и обновится.

## Как обновлять в будущем
Когда я (Claude) присылаю новую версию кода:
1. Замените файлы в папке `LegoLessonApp` на новые (как раньше — извлечь архив
   поверх старой папки, `node_modules` не пострадает)
2. В `package.json` поднимите номер версии (`"version": "1.0.1"` и т.д.)
3. Повторите Шаг 4 и Шаг 5 этой инструкции

## Структура
```
LegoLessonApp/
  main.js              # главный процесс Electron
  preload.js            # безопасный мост к интерфейсу
  renderer/              # HTML/CSS/JS интерфейса
  engine/                 # тот самый пайплайн (content.json, скрипты, ассеты)
    scripts/
      generate-content.js  # НОВОЕ: AI пишет content.json по одному слову темы
      ...остальное как раньше
  package.json
```
