# Preschool Lesson Presentation — Rulebook

Свод правил для создания LEGO-уроков английского языка формата **Preschool (3-5 лет)**, для детей, не говорящих по-английски (Вьетнам). Основано на разборе реальных презентаций (Ice Cream, Pineapple, Fish) и полной сборке эталонного примера (Candy Cane).

---

## 1. Команда ролей

| Роль | Задача |
|---|---|
| **Методист-адаптатор (куратор)** | Обучен методологии пользователя; финальный контроль структуры; остальные роли подчиняются ему |
| **Копирайтер презентаций** | Пишет 3 текстовых слоя на слайд: заголовок/вопрос, детская фраза (крупно, повторяемая), реплика-подсказка учителю (мелко); адаптирует английский под вьетнамских детей |
| **Визуальный дизайнер (арт-директор)** | Не ищет готовые картинки — пишет точные промпты для ChatGPT; пользователь генерирует и присылает результат; дизайнер оценивает подходит/нет + почему |
| **Эксперт-предметник** | Проверяет, что упрощение не искажает факты |
| **Редактор/корректор** | Проверяет только форму текста (орфография, пунктуация, единообразие) — НЕ меняет смысл/методологию без разрешения |
| **Сборщик (Technical Assembler)** | Собирает PPTX: анимации переходов, читаемость, вставка медиа |
| **Ревьюер "глазами ученика"** | Проверяет восприятие 3-5-летним ребёнком без знания английского — считывается ли смысл по картинке |
| **Сценарист историй (Story Writer)** | См. раздел 6 |
| **QA-валидатор** | См. раздел 8 |

Целевая аудитория может **не знать ни одного слова по-английски** на старте. Текст истории и реплик — это в первую очередь текст ДЛЯ УЧИТЕЛЯ (он разыгрывает интонацией/жестами), а не текст, понятный детям на слух. Смысл доносится через картинку, жест, повтор 1-2 ключевых слов — не через понимание фраз целиком.

## 2. Порядок слайдов (полная структура урока)

Итого 24 слайда (подтверждено на реальном референсе Candy Cane):

1. **Cover** — название темы на цветном фоне с декором. **БЕЗ фото/картинок** — только текст (см. STYLE_COVER в DESIGN_SYSTEM.md). Отдельного слайда с фото фоновой LEGO-модели истории НЕ существует — сам факт того, что дети строят объект темы, устанавливается через Model Building/Our Goal, а не через отдельный "фон истории".
2. **Intro video** — весёлое видео с движением/танцем (см. раздел 4)
3. **Story** — история (см. раздел 5). Ведёт к постройке МОДЕЛИ ТЕМЫ, не производного объекта (см. раздел 5, критичное правило).
4. **Story Props** — пропсы для истории, зеркало печатных материалов (см. раздел 3)
5. **Model Building** (шаблонный титульный слайд)
6. Фото РЕАЛЬНОГО объекта темы (не LEGO) — **сразу после Model Building**, без подписи
7. **Our Goal** — можно разделить на 2 половины: слева лёгкая версия модели, справа сложная; заголовок по центру сверху
8. **Step by Step** — шаг-за-шагом сборка (см. раздел 3)
9. **Presentation** — Q&A после сборки, минимум 4 пары (см. раздел 5)
10. **Game 1** — активная игра, единый script-формат (см. раздел 9)
11. **Game 2** — когнитивная/STEM игра, единый script-формат (см. раздел 9)
12. ABC Song video (шаблон/заглушка)
13. **Which letter?** — это и есть Алфавит-слайд (общий на все уроки, см. DESIGN_SYSTEM.md), учитель водит по буквам, дети угадывают букву темы; меняется только подпись снизу
14. Letter-specific видео (фоника буквы)
15. **What letter is it?** — большая буква (см. раздел 7)
16. **Pattern Sheet** — схема буквы из кирпичиков
17. **Game 3** — активная игра с построенными моделями, единый script-формат
18. **Challenge / Free Play** — объединённый слайд. Сюда, а не в основную модель, идут производные объекты (например аквариум для рыбки)
19. Model Building (повтор, шаблон)
20. **Clean Up**
21. **Wrap up** (шаблон)
22. Повтор буквы (та же большая буква)
23. **What is this?** — тот же реальный объект (см. п.6)
24. Closing video (шаблон/заглушка — "fingers and toes")

Шаблонные слайды, одинаковые во всех презентациях: текстовые титулы-переходники ("Model Building", "Clean Up", "Wrap up"), Алфавит-слайд (кроме подписи снизу) и два видео (ABC Song, closing) — константы. Все остальные слайды уникальны под тему.

## 3. Фото и печатные материалы

- **Слайд 4 (Story Props)** — не просто коллаж-референс, а зеркало печатных материалов: картинки идентичны тому, что печатается в PDF как физические пропсы для истории. Учитель распечатывает и вырезает их для рассказа.
- **Step-by-step фото сборки**: 1 фото шага = 1 слайд, без объединения/пропусков. Количество не фиксировано (5–20+). Пользователь сам готовит и присылает уже обработанные фото (фон убран/зачищен — белый или прозрачный, яркость/качество повышены, тень от модели сохранена) — просто кладёт готовые файлы в `assets/steps/<topic>/`, откуда их подхватывает сборщик. Автоматическая обработка фото (пробовали через classical CV) отключена — качество на сложных фото (белое на белом, мягкий фокус) получалось хуже ручной обработки, решили не усложнять.
- **Фото фоновой LEGO-модели истории** и **фото реального объекта темы** — см. порядок в разделе 2. Реальное фото → дети строят по представлению/воображению, а не копируют точную схему. Этот же принцип (не обязательно буквальное LEGO-изображение) применим и к иллюстрации Challenge — фото-референс может быть условным (например, конфета в обычной коробке как референс для "построй коробочку из LEGO").
- **Игра 1/2/3, если использует printout** — этот же printout обязательно идёт в PDF.
- **PDF** должен включать: печатные пропсы истории, печатную иллюстрацию фона истории (отдельно от физической LEGO-модели), printout-ы игр, готовую Pattern Sheet буквы, и **отдельную страницу с ПОЛНЫМ текстом истории** (как в заметках докладчика) — чтобы у учителя был скрипт на бумаге.

## 4. Видео

- **Intro video (слайд 2)**: приоритет 1 — весёлое, с движением, чтобы вовлечь детей танцевать; приоритет 2 — тематическая связь с темой ИЛИ с фоном истории. Если связано с фоном истории — можно не менять весь блок 6-10 уроков.
- **ABC Song и Closing video** — временные заглушки, одинаковые во всех презентациях, пользователь планирует разнообразить позже.
- Дизайн видео-слайдов: тёмный "кинотеатральный" фон, видео вставляется как реальный кликабельный онлайн-плеер (не картинка-плейсхолдер), ссылка "Link to Youtube" снизу как резерв.

## 5. Story, Observation, Presentation

**Драматургия Story (фиксированная):**
1. Разминочное видео снимает энергию
2. Дети садятся, яркая завязка
3. Интерактивная часть — учитель вовлекает репликами
4. Появляется главный объект темы (LEGO-модель), взаимодействует с детьми
5. Мост к "давайте это построим"
6. **Observation** — разбор частей объекта, что строить первым/дальше; тема продолжает обсуждаться и во время Model Building, не только один раз.

⚠️ **КРИТИЧНОЕ ПРАВИЛО (найдена реальная ошибка на теме Fish):** мост "давайте
это построим" должен вести к постройке МОДЕЛИ САМОЙ ТЕМЫ, а не производного/
связанного объекта. Пример ошибки: тема "Fish" → история вела к постройке
"LEGO-домика для рыбки" вместо самой рыбки. Правильно: история ведёт к постройке
рыбки; домик/аквариум для рыбки — это материал для Challenge (см. раздел 9),
а не для основной модели Model Building. Перед сдачей проверять: то, что дети
строят на Model Building — это буквально предмет из заголовка урока?

⚠️ **ВТОРОЕ КРИТИЧНОЕ ПРАВИЛО (найдена ошибка на теме Snake):** каждый ребёнок
всегда строит СВОЮ ПОЛНУЮ модель с нуля — дети никогда не "достраивают" или
"чинят" модель персонажа из истории. Если у персонажа истории есть проблема
(например "змея Sammy слишком короткая"), решение НЕ "давайте удлиним Sammy",
а "давайте каждый построит свою собственную длинную змею". Мост к постройке
должен звучать как призыв каждому ребёнку построить свой экземпляр, а не как
доработка существующего объекта.

**Presentation (после сборки):**
1. Простые вводные вопросы (имя, возраст)
2. Вопросы про модель/тему — ДОЛЖНЫ опираться на то, что реально обсуждалось в Story/Observation. Частая ошибка: спрашивать про свойство, которое не вводилось раньше (например "он шершавый?" без предварительного тактильного знакомства) — сначала вводим сенсорную информацию в Story/Observation, потом спрашиваем.
3. **Минимум 4 пары вопрос-ответ** (не 3) — больше материала для взаимодействия с классом.

## 6. Роль "Сценарист историй" — детальные правила

- Тренируется быть независимой: сама выбирает пол персонажа-ведущего и другие творческие решения в рамках правил, не переспрашивая каждый раз.
- **Сюжет сквозной**: истории одного блока (6-10 уроков) продолжают друг друга как сериал.
- **Персонаж-ведущий**: постоянная LEGO-минифигурка (мальчик/девочка/оба), не абстрактный/животный персонаж. Имя = имя реального учителя (учитель играет "версию себя" в LEGO-мире), пол минифигурки под пол/имя учителя. В черновике — плейсхолдер `[TEACHER NAME]`.
  ⚠️ **ОБНОВЛЕНО по калибровке (ошибка на теме Airplane):** не изобретать
  дополнительных именных человеческих персонажей (например "Captain Ace"),
  если по сюжету нужна человеческая роль — это ВСЕГДА минифигурка учителя.
  Именные персонажи допустимы только когда они олицетворяют САМУ ТЕМУ урока
  (Sammy the Snake, Bubbles the Fish, Freddy the Frog) — то есть без них
  сюжет не построить, а не просто "для интереса".
- **Формат вывода** (всегда в этом порядке, на английском):
  1. Краткое содержание истории — первым
  2. **Materials** сразу после: Background / Characters (первым — персонаж-ведущий с пояснением "LEGO boy/girl minifigure representing the teacher") / Objects. **Characters должен быть виден на самом слайде**, не только в заметках докладчика.
  3. Полная история (может быть длиннее 5-8 предложений), с репликами и жестами-ремарками — в заметках докладчика.
- Внутри полной истории — обязательны моменты **call-and-response** (дети хотят повторить хором за учителем), например хоровое приветствие нового персонажа.
- Действия персонажей описываются ОБЩО, без привязки к конкретному реквизиту (например "конфета появляется", а не "выпрыгивает из коробки") — реализацию придумывает каждый учитель под свои пропсы.
- Для мотивации построить объект можно ввести простой конфликт через второго персонажа (опционально).
  ⚠️ **ОБНОВЛЕНО по калибровке (ошибка на теме Frog):** конфликт должен быть
  конкретным и разыгрываемым 2-3 бумажными пропсами на столе, не абстрактным.
  Тест: "смог бы учитель физически показать это парой вырезанных картинок
  перед детьми 3-5 лет?" Плохо: "не может найти сухое место", "расстраивается"
  (абстрактно, нечего вырезать). Хорошо: конкретное взаимодействие с другим
  простым, узнаваемым объектом/существом (лягушка пытается поймать комара —
  комар легко рисуется как пропс и всем понятен).

## 7. Буква темы

- После видео с алфавитной песней учитель проходит по буквам по порядку (указывает на экране), дети реагируют, пока сами не угадают букву, с которой начинается тема (например, pineapple → P).
- После угадывания — **letter-specific видео** (фоника конкретной буквы).
- **Слайд "What letter is it?"**: большая буква по центру, цвет = тот же, что у этой буквы на слайде алфавита; заголовок сверху, подпись снизу ("Have students drill the letter and sound chorally and individually"); в заметках докладчика — пронумерованный мини-скрипт (show card / sound / connect to topic / children repeat / worksheet / build letter).
- **Повтор буквы в конце урока** — точная копия того же оформления (размер/цвет/шрифт), без лишнего фото.
- **Pattern Sheet**: готовая схема кирпичиков для буквы, дизайнер НЕ рисует — только выбирает нужную букву из готового набора (источник: PDF-набор вида Bricks4Kidz Aa-Zz, единожды очищенный от водяных знаков; все 26 букв извлекаются заранее для переиспользования).

## 8. Визуальное оформление

- **Названия слайдов**: тёмно-серым (не цветным), в компактном боксе, центрированном по горизонтали, у верхнего края слайда.
- **Видео-слайды**: тёмный фон, реальный кликабельный онлайн-плеер + ссылка-резерв снизу.
- **Никаких длинных тире (—)** в тексте — заменять на запятые/двоеточия (не должно выглядеть "ИИ-сгенерированным").
- **Числа в обычных фразах-предложениях — словом** ("One toy dollar"), но нумерация меток (Game 1, Game 2) — цифрой, это нормально.

**Роль "QA-валидатор"** — обязательный последний шаг перед каждой отправкой файла:
1. Ни один элемент не выходит за границы слайда (x+w и y+h ≤ размеры холста)
2. Картинки не наезжают на декор/друг на друга
3. Изображения не искажены (пропорции сохранены)
4. Орфография/опечатки
5. Соответствие правилам раздела 8 выше

## 9. Игры

**Формат подачи правил (ОБНОВЛЕНО дважды по фидбеку):** все три игры описываются
единым структурированным `script` (массив реплик с полем `speaker`), а не
сплошным текстовым абзацем — иначе учителю тяжело быстро считать правила
глазами перед уроком. Прямая речь (что говорят дети / что отвечает учитель)
выделяется ТОЛЬКО цветом (синий = дети, красный = учитель), БЕЗ жирного
начертания и подчёркивания — это оказалось лишним визуальным шумом. Действия —
обычным текстом (italic, серый), отдельным абзацем. Единый стиль на всех трёх
игровых слайдах.

- **Game 1**: всегда активная, физическая. Подтверждённый рабочий паттерн — дети САМИ хором инициируют реплику-вопрос ("Teacher, teacher, what do candy canes do?"), учитель отвечает командой на действие, дети выполняют + чант, после паузы спрашивают снова, учитель даёт новое действие, обычно завершается тем, что учитель играет антагониста из истории и "ловит" детей. Важно: дети — инициаторы реплики, не только повторяют за учителем.
- **Game 2**: менее активная, ближе к "реальному миру" — STEM/эксперимент, matching, сортировка. Использует printout.
- **Game 3**: активная, но менее чем Game 1 (дети только что строили). Обязательно использует построенные модели. ⚠️ ОБНОВЛЕНО: нужны ДВЕ явно различающиеся команды учителя со сменой скорости движения моделей (медленно/быстро), каждая с понятной причиной, привязанной к теме (например для змеи: "sunny day, slither slow!" vs "storm is coming, slither fast!") — простое "беги к дереву" без объяснения причины смены темпа было признано непонятным.

**Challenge — разнообразие архетипов (добавлено после повторения одного и того же типа "домик/гнездо" несколько уроков подряд):** ротировать между модификацией+измерением (обязательно с измеримым/сравнительным элементом — "просто побольше" недостаточно), измерением/сравнением (особенно хорошо как callback к конфликту истории), средой обитания/контейнером (не через раз по умолчанию), семьёй/группой моделей. Подробности — в CONTENT_GENERATION_GUIDE.md.

⚠️ **КРИТИЧНОЕ ОГРАНИЧЕНИЕ (найдена ошибка на теме Butterfly):** архетип
"функция/механизм" (движущиеся части — машущие крылья, катящиеся колёса)
**НЕДОСТУПЕН для Preschool.** Preschool-модели строятся ТОЛЬКО из простых
кубиков 2×4 и 2×2, без механики — это физически невозможно на этом наборе.
Движущиеся части — тема для Brickmoto (6-9 лет), отдельная методика на
будущее. Не предлагать этот архетип для Preschool ни при каких условиях.

⚠️ **ВТОРОЕ КРИТИЧНОЕ ОГРАНИЧЕНИЕ (найдена ошибка на темах Airplane/Turtle):**
Challenge — ВСЕГДА про постройку, НИКОГДА про физический тест уже готовой
модели (бросить, толкнуть, покатить, гонка). LEGO-модели хрупкие и
рассыпаются при таком обращении. Любое измерение/сравнение — на самой
конструкции по мере постройки (сколько кирпичиков, высота/ширина/длина), не
через движение. Ошибка: "race to see whose airplane flies farthest with a
push" / "how far can your turtle walk in five pushes" — исправлено на
"build the tallest hangar" / "build the biggest shell, count the bricks".

**Видео (ОБНОВЛЕНО после реальной поломки):** youtube id для intro-видео и letter-specific видео НИКОГДА не восстанавливать по памяти — только через web_search в текущем чате, с id из реального результата поиска. После сборки презентации `qa-validate.py` (при наличии content.json вторым аргументом) автоматически проверяет доступность каждого используемого id через YouTube oEmbed.
