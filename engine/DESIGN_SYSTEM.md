Каждая реплика — отдельный абзац (breakLine + пустая строка-отступ между репликами), выравнивание LEFT, 18pt.

Game 2: текст-script слева (x=0.8,y=1.85,w=5.3,h=4.9), визуал (цвета/фигуры/printout) справа (x=6.5,w=5.3).

## PDF (сопроводительный, для печати)
Letter-формат (612×792pt, НЕ A4!). Заголовок каждой страницы: Helvetica-Bold 20pt, `404040`, центр, y="page_height - 50". Под заголовком красная линия 2pt, `D03331`, от x=50 до x=562, y="page_height - 62".
Секции внутри текста (Short Summary/Materials/Full Story/Observation): Helvetica-Bold 13pt `D03331`.
Обычный текст: Helvetica 11pt чёрный.
Футер (мелкие инструкции): Helvetica-Oblique 10pt, серый `888888`.

**Точный порядок и структура 5 страниц** (подтверждено на реальном референс-файле CandyCane_Printables.pdf):
1. **Story Props** — единственная страница, где есть текст: заголовок сверху ("Story Props — Cut Out & Use During Storytelling"), под каждой картинкой-пропсом короткая подпись-название (например "Umbrella", "Raindrops"), одна строка-инструкция внизу ("Print, cut out, and use as hand props while telling the story."). Сами картинки пропсов — без текста НА себе.
2. **Story Background** — full-bleed на весь вертикальный лист, БЕЗ подписей/заголовков. Если исходная картинка горизонтальная — поворачивается сама картинка на 90° (не страница), обрезка по краям допустима, искажать пропорции нельзя.
3. **Full Story Script (for the Teacher)** — структурированные разделы с подзаголовками именно в этом порядке: **Short Summary** (короткий абзац) → **Materials** (строки Background / Characters / Objects) → **Full Story** (полный диалог с ремарками, как в заметках докладчика слайда Story) → **Observation** (вопросы для обсуждения после истории/перед сборкой).
4. **Printout игры** (например Game 2 matching) — БЕЗ текста на странице вообще.
5. **Pattern Sheet** — небольшой заголовок сверху вида "Build the Letter X — Brick Pattern", картинка буквы ~90% от максимального размера, центрирована.

Общие тех. правила: обложка не нужна — сразу с 1 страницы материалы; ВСЕ страницы одного вертикального формата (portrait); составные картинки компоновать в портретной пропорции и авто-кропить пустые поля; любая распечатка для ручной работы детей — крупная, без больших пустых полей.

**КРИТИЧНО**: картинки в PDF должны быть ТЕМИ ЖЕ файлами, что и в презентации (например `prop_umbrella.png`), вставленными через contain-fit (сохранение пропорций, без искажения) — НЕ создавать свою отдельную обрезанную (autocrop) версию специально для PDF, самодельная обрезка может получиться неровной и разойдётся с презентацией.

## Видео (важно!) — ОБНОВЛЕНО, 4 видео-слайда с разной логикой каждый
Видео вставляется в PPTX как РЕАЛЬНЫЙ кликабельный онлайн-плеер (если id есть):
```js
slide.addMedia({ type: "online", link: `https://www.youtube.com/embed/${youtubeId}`, x, y, w, h });
```
Визуально: тёмный фон `141414`, серая рамка-плеер (457200,411480,11247120,5486400), подпись видео под рамкой 13pt `AAAAAA`, "Link to Youtube" 15pt `6FB6FF` внизу (только если id есть) — кликабельная гиперссылка на обычный youtube watch-URL.

**1. Intro video (слайд 2)** — под тему урока, id не задаётся автоматически (AI не может проверить видео в реальном времени — см. правило ниже). Слайд рендерится как ПЛАШКА "🎬 INSERT VIDEO HERE" с подписью-подсказкой под темой.

**2. Alphabet song (слайд 12, константа на все уроки)** — youtube id `ezmsrB59mj8` (задан пользователем напрямую, не через web_search).

**3. Letter-specific video (слайд 14)** — по букве темы, id берутся из `scripts/letter-videos.json` (полный список на все 26 букв предоставлен пользователем напрямую).

**4. Closing video (слайд 24)** — ОБНОВЛЕНО: больше не константа. Ненадёжность встроенного YouTube-плеера в PowerPoint (реальная проблема на стороне Microsoft, воспроизводимая у пользователя) сделала фиксированное видео нецелесообразным. Слайд теперь тоже ПЛАШКА "🎬 INSERT VIDEO HERE" — учитель/пользователь сам вставляет подходящее закрывающее видео.

⚠️ **Обычная неполноценная плашка (youtubeId=null) — это нормальное ожидаемое поведение для intro и closing**, не баг: `videoSlide()` в build-pptx.js сама рисует крупную серую надпись-подсказку вместо плеера, если id не передан. НЕ пытаться подставлять id для этих двух слайдов автоматически по памяти.

**Для letter-specific видео (единственное место, где новый id иногда может понадобиться, если пользователь добавит новую букву в список)** — id ИСКЛЮЧИТЕЛЬНО из `scripts/letter-videos.json` или через `web_search`, никогда по памяти. После сборки презентации `qa-validate.py` проверяет доступность через YouTube oEmbed (`https://www.youtube.com/oembed?url=...&format=json`): код 404/401 = видео точно недоступно (жёсткая ошибка), другие коды = предупреждение (может быть сетевым ограничением на машине). Проверка требует интернет на машине пользователя.

**Letter-specific видео (фоника буквы)** — ВСЕГДА брать из плейлиста пользователя:

## Буква "Pattern Sheet" — источник
Файл `Letter_pattern_sheets_AaZz_Revised_9_19.pdf` (в файлах проекта) — 52 страницы, 2 страницы на букву, порядок строго алфавитный: буква с индексом n (A=0) занимает страницы (2n+1, 2n+2) 1-indexed. Пример: R = 18-я буква (n=17) → страницы 35-36.
Перед использованием ОБЯЗАТЕЛЬНО убрать водяной знак Bricks4Kidz: бинаризация по порогу (pixel<150 → чёрный, иначе → белый) полностью убирает водяной знак, не трогая чёрные линии кирпичиков.
⚠️ Точная идентификация буквы на странице не проверяется автоматически (OCR не читает буквы, собранные из значков) — просить пользователя визуально подтвердить один раз при первом использовании новой буквы.

## Технический QA (обязательно проверять каждый раз)

⚠️ XML/schema-валидация (validate.py / python-pptx bounds) НЕ ловит переполнение текста внутри textbox — она проверяет только структуру XML, не реальную вёрстку. **Обязательный шаг**: рендерить в PDF (`soffice --convert-to pdf`) и программно проверять реальные bounding box каждого слова/картинки через `pdfplumber` (`page.extract_words()` / `page.images`), флагая всё, что выходит за границы страницы.

**Известные баги и как их избегать:**

- **Двойной перенос строки (pptxgenjs).** Одновременное использование `"\n"` внутри текста И опции `breakLine: true` в объекте run создаёт ДВОЙНОЙ перенос и раздувает высоту текста в 1.5-2 раза, из-за чего он вылезает за края слайда. Правило: использовать ТОЛЬКО `breakLine: true`, без `\n` в самой строке; для пустой строки-отступа — отдельный run с `text: ""` и `breakLine: true`.

- **Подмена шрифта.** Шрифты не из стандартного набора (например Comic Sans MS на алфавит-слайде) могут быть недоступны в среде рендеринга → подменяются на более широкий шрифт → однострочный текст переносится на вторую строку и "уплывает", сбивая вертикальную раскладку соседних блоков. Подбирать размер с запасом (чтобы даже при замене шрифта текст не переносился) и/или задавать `wrap: false`.

- **Тихий silent-drop (reportlab Frame).** Если высота `Frame` впритык равна высоте текста (например 20-30pt под однострочный заголовок), `Frame.addFromList()` МОЛЧА не рисует параграф вообще — ни ошибки, ни исключения, просто пусто. Правило: закладывать высоту с большим запасом (минимум 40-45pt для строки текста 14-17pt с учётом leading/spaceAfter), и после генерации PDF обязательно проверять через `pdfplumber`, что весь ожидаемый текст реально присутствует на каждой странице.

- **Кривые фигуры от ручных векторных путей.** Ручные пути через `reportlab.canvas.beginPath()` + `arcTo`/`curveTo` с вычисленными вручную координатами — легко ошибиться в математике угла/кривой, фигура выйдет перекошенной без единой ошибки выполнения. Для простых иконок в PPTX — использовать нативную preset-геометрию (`prstGeom`, например pptxgenjs `addShape("pie", {angleRange:[180,360]})`) — это стандартная, проверенная геометрия PowerPoint, не кастомный путь.

- **pptxgenjs `sizing: {type:"contain"}` растягивает картинку до box, а НЕ вписывает с сохранением пропорций** (несмотря на название) — именно так исказилась буква на Pattern Sheet. Правильный способ: прочитать реальные width/height файла (PNG: IHDR chunk байты 16-23; JPEG: SOF0/SOF2 маркер) и вручную посчитать contain-fit (scale = min(boxW/imgW, boxH/imgH), центрировать в box), передать в `addImage` уже готовые x/y/w/h БЕЗ параметра `sizing`.

- **Перекраска картинки для игр matching (правильный способ).** Если нужны цветные варианты одной и той же картинки (например зонтик в 6 цветах) — НЕ рисовать иконку заново (ни вручную, ни через PIL с нуля), а взять РЕАЛЬНУЮ картинку, уже использующуюся в презентации, и перекрасить через HSV hue-shift: конвертировать в HSV → определить исходный доминирующий оттенок (мода H-канала по насыщенным пикселям) → сдвинуть канал H на дельту до целевого цвета палитры, оставить S/V как есть → конвертировать обратно. Форма и вся светотень остаются идентичны оригиналу — это тот же файл, только с другим оттенком. После перекраски проверить результат тем же способом (доминирующий H должен совпадать с целевым).
